# 实时追踪与持续更新

加载时机：用户提供基线、需要连续追踪，或话题属于多阶段事件/长期趋势。快讯档且无基线时只读 SKILL.md §3.6 快讯模板即可，不必加载本文件。

## 目录
1. 时间管理 2. 连续追踪 3. 更新机制 4. 热点生命周期 5. 基线匹配与热度回落 6. 关联话题与关系

## 1. 时间管理（按话题类型）
- 突发事件：关注近期进展，并回溯起因
- 历史议题：关注关键历史节点
- 技术路线：梳理演进与当前状态
- 行业趋势：结合长期数据与近期变化
重要信息标明发生时间、发布时间与必要的截至日期，统一按报告头声明的展示时区（SKILL.md §3.3）。

## 2. 连续追踪
每篇文章/简报都必须能独立阅读。对持续追踪的话题：简要交代必要背景、说明此前状态、突出本次新增进展、分析新进展对原有判断的影响、避免复制整篇历史报告。

## 3. 更新机制
按事件重要性与发展速度决定更新频率；重要新消息及时评估；只有足以改变原有判断的信息，才需要调整核心结论。更新旧文章时：正文保持最新状态、保留重要更新记录、说明更新时间与关键变化。

## 4. 热点生命周期
热度下降不代表话题失去价值。根据生命周期调整追踪频率，必要时从短期热点转向长期专题。主动发现有可靠证据支持的早期信号与潜在趋势。

## 5. 基线匹配与热度回落（执行规则见 SKILL.md §3.6）
- 基线 = 用户粘贴的上一份完整简报（00–06 全文），本次会话内使用，不落盘、不依赖对话历史；只有事实列表时须说明缺少哪些段。
- 保留基线已有 Fnn/Tnn 编号，新增用不冲突的新号；只有事件主体与具体事件一致才配对，仅主题相近不算同一条。
- 🆕新增 / 🔄修正 / 📈进展 / 📉热度回落四类互斥，同一事实既有新进展又修正旧描述时拆成两条；找不到可靠对应就不强行比较，不制造假趋势。
- "没有新消息"不标 📉，写"未检出新进展"；📉 须满足同平台 + 同指标 + 同采样窗 + 同采集口径四项，覆盖受限导致的"未检出"不算回落。
- 00 段无基线写"未提供基线，本次不比较"，保留本节。

## 6. 关联话题与关系（深度档可选模块）
仅深度理解档且话题涉及多个子话题/相关方时启用，在 05 之后加一节"关联话题与关系"：
- 只陈述可验证的关联（共享参与方 / 共享资源 / 时间先后 / 叙事引用关系）及其依据（挂 Fnn 或 Enn）；
- 不推断未经验证的因果关系，不建完整知识图谱；
- 关联强度用文字描述（明确 / 可能 / 仅时间相近），不用数字打分；
- 无可靠关联依据时写"未检出可验证的关联"，不凑数。
